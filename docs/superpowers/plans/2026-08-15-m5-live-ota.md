# M5 Live OTA + Push + Entitlement + Retention Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal (spec §9 M5):** Live content OTA (backend → app, atomic), local notification for timer completion with permission-denied fallback, entitlement integration with the M1 backend (receipt validation + content gating), and retention instrumentation (§9 M5 / A4 amendment). This is the final milestone: after M5 the app is store-prep ready pending external credentials (Apple/Google accounts, Firebase project).

**Architecture:** `ContentService` (lib/content/content_service.dart) drives OTA: GET `/api/content/manifest` (bearer token from session) → compare `content_version` with active bundle → if newer, download each file to a staging dir → `ContentActivator.activate(stage, activeDir)` (M2-5, already atomic). `NotificationService` (lib/notifications/notification_service.dart) wraps `flutter_local_notifications` behind an interface; tests use a fake. Timer completion triggers a local notification when permissions allow; when denied → in-app banner (spec §6: notification-independent accuracy). Entitlement: after login, `GET /api/billing/entitlement` → cached in Drift UserSettings → `EntitlementGate` widget shows a calm locked state (I1) on premium screens when expired. Receipt submission: `PlatformReceiptProvider` abstraction (real StoreKit2/PlayBilling impl requires store credentials — M1 verifier-registry precedent) posting to `POST /api/billing/receipt`. Retention: `retention_events` table (schema v3 additive) + `RetentionService.record(event)` at checkpoints/submissions/timer-finish + weekly-retention query test (§9 M5 instrumentation).

**Tech Stack:** Flutter 3.44.1, drift (schema v3), http (existing ApiClient M2-7), flutter_local_notifications (only new dep; plugin registration is manifest-only, no credentials needed). Tests `--no-pub`; Windows `rm -rf build/unit_test_assets` pitfall.

## Global Constraints

- G1: All network paths go through `ApiClient` (token header); no raw http in screens. Tests inject `FakeApiClient` (M2-7 subclass pattern).
- G2: OTA is never automatic-push-to-active: download stage → verify → atomic activate (M2-5). Any failure: active untouched, next launch retries.
- G3: Entitlement checks are advisory UI gating (I1, calm locked state) — a failed network check never bricks the app; content already on device stays renderable offline (§7.1).
- G4: Notifications: permission-denied → in-app fallback (SnackBar), never silent failure; timer accuracy never depends on notifications (spec §6).
- G5: Retention events: append-only, timestamps ISO-UTC, no PII beyond existing local identifiers; instrumentation is local-only (Invariant 6).
- G6: Schema v3 = additive (retention_events only); v2→v3 migration tested.
- G7: FCM/APNs remote push = documented interface stub (needs Firebase project + store credentials — external open items); local notifications fully working now.
- G8: Store prep checklist lands as `docs/store-prep-checklist.md` (verified against M1 §10.3 A2 copy + A1 pricing + open item 2) — the deliverable that closes the M0 "verify before submission" open item.
