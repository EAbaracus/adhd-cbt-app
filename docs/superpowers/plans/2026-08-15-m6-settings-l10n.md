# M6 Settings + Localization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** (1) Settings screen — account (logout, delete account via backend `DELETE /api/auth/me`), 988/NATHELP crisis banner (A2), language selector; (2) TR localization architecture — content `tr` keys (schema optional), locale-aware models, AppLocale scope, UI string layer — with session 1-2 + symptom-checklist as translated exemplars. Post-MVP hardening (store-prep checklist items #12, #15).

**Architecture:** Session persistence: login/register → token + email stored in Drift `user_settings` (`auth_token`, `auth_email`); `ApiClient.token` restored at bootstrap. AppScope gains `ApiClient` (created in main, shared). Settings reads scope; delete account → `DELETE /api/auth/me` (backend M1) → on 200 wipe auth keys + entitlement → navigate to onboarding. Crisis banner: static card, always visible (supportive framing, A2 copy). Localization: content schema `localized` gains optional `tr` (string for titles, string[] for content); `AppLocale` InheritedWidget (en default, persisted `locale` in user_settings); models gain `titleFor(Locale)`/`contentFor(Locale)` fallback en; UI strings via dependency-free `AppStrings` (en/tr maps) — applied to settings + home + onboarding; remaining screens follow the same pattern (documented).

**Tech Stack:** Flutter 3.44.1, Drift (schema v3 unchanged — user_settings is key/value), existing ApiClient/AppScope. No new deps. Tests `--no-pub`; Windows `rm -rf build/unit_test_assets` pitfall.

## Global Constraints

- G1: `lib/l10n/` and model changes pure Dart; only screens import Flutter.
- G2: Delete account is destructive: confirm dialog requires typing confirmation (`delete`) — no one-tap.
- G3: Locale fallback chain: `tr` → `en`; missing key never crashes (empty string acceptable, never exception).
- G4: Auth token persisted; logout clears token/email but NOT progress (local-first §7.1); delete account clears auth keys only (server cascades sync data; local progress stays — documented, matches M1 DELETE semantics).
- G5: Schema change is backward-compatible: `tr` optional, `en` still required — old bundles validate.
- G6: Crisis banner copy: EN "If you're in crisis… call or text 988 (US)" / TR "Krizdeyseniz… 112 / RUH SAĞLIĞI DESTEK HATTI 112" (NATHELP TR equivalent) — static, non-alarming.
